# Registration and output spaces

MRSIPrep registers a native MRSI reference to the subject's T1w image,
then registers T1w to MNI152NLin2009cAsym when MNI output or atlas projection
is needed. Registration settings and the requested output grids are separate
choices. Review both overlays in the [QC report](outputs.md).

## Choose a registration backend

| Backend/settings | MRSI → T1w | T1w → MNI |
|---|---|---|
| ANTs (default) | Rigid + SyN, `--ants-mrsi-to-t1-transform sr` | Rigid + Affine + SyN, `--ants-t1-to-template-transform s` |
| FSL, default deformable setting | FLIRT (default 6 DOF) followed by FNIRT | FLIRT affine (default 12 DOF) |
| FSL with `--no-fsl-deformable` | FLIRT only (default 6 DOF) | FLIRT affine (default 12 DOF) |

Select FSL with `--registration-backend fsl`. FNIRT applies to the
MRSI→T1w stage; it does not add deformable T1w→MNI normalization. See the
[registration benchmark](registration_benchmark.md) for the configurations
actually evaluated there, which include a different FLIRT DOF setting.
The [CLI reference](cli_reference.md) lists transform and optimizer controls.

For a default ANTs run with an explicit 2 mm MNI output grid:

```bash
mrsiprep-docker /path/to/bids /path/to/derivatives participant \
  --participant-label S001 --session-label V1 \
  --metabolites CrPCr,GluGln,GPCPCh,NAANAAG,Ins \
  --ref-met CrPCr \
  --registration-backend ants \
  --output-spaces MNI152NLin2009cAsym:res-2 \
  --nthreads 8
```

### Existing transforms and legacy normalization flags

`--normalization existing` requires the expected forward and inverse
T1w→MNI files to exist under the recording's transform directory. It fails
if those files are absent. An arbitrary transform from another pipeline
must first be made compatible with the selected backend's format, naming,
and reference spaces; passing this flag alone does not import it.

`--normalization simple` is a legacy default name. It uses the selected
registration backend, including SyN with default ANTs settings; it does not
mean an affine-only fit. The legacy `ants-syn` value is also accepted, but
current registration dispatch follows `--registration-backend`. For new
commands, set the backend and transform options directly.

## Anatomical registration target

`--registration-t1-target` chooses `brain`, `brain-csf`, or `raw`. The default
is `brain` for SynthSeg parcellation and `brain-csf` for atlas/Chimera modes.
`brain-csf` adds CSF back to a skull-stripped T1w target, so ventricular
signal is represented in the registration target. It requires a CSF
probability map, generated by the default tissue backend or supplied as
CAT12 `p3` for the other tissue settings.

`--csf-pv-threshold` sets the CSF probability needed for inclusion (default
`0.95`). For example:

```bash
  --registration-t1-target brain-csf --csf-pv-threshold 0.5
```

A lower threshold includes more borderline-CSF voxels. When tissue
processing is disabled and no `p3` map exists, select a compatible `brain`
or `raw` target instead.

## Choose output spaces and resolution

`--output-spaces` accepts `MRSI`, `T1w`, and `MNI152NLin2009cAsym`, with
case-insensitive aliases `mrsi`, `t1w`, and `mni`. MNI is the default.
Native intermediate maps are retained independently of this selection.
For example:

```bash
  --output-spaces MNI152NLin2009cAsym:res-2 T1w
```

For MNI output, `res-` accepts:

| Modifier | MNI target spacing |
|---|---|
| `res-origres` (default) | Mean native MRSI voxel dimension, rounded to integer millimetres |
| `res-t1wres` | Mean T1w voxel dimension, rounded to integer millimetres |
| `res-2`, or another positive integer | Explicit isotropic spacing in millimetres |

These modifiers replace the old global `--mni-resolution` flag. The
T1w→MNI registration target uses T1w-derived spacing when the MNI choice
is `origres`; the final MNI maps use MRSI-derived spacing. These grids
therefore need not have the same resolution. A finer output grid does not
increase the MRSI acquisition's spatial resolution.

Requesting T1w output also enables `--output-mrsi-t1w`. Full T1w maps use
the anatomical reference grid and are opt-in; the registration report
always generates its own single reference-metabolite overlay in the work
directory. The current T1w resampler uses that reference grid even if a
`res-` qualifier is attached to `T1w`.

CRLB, shared SNR, and linewidth maps are resampled with the signal maps
when available. Per-metabolite spike masks are additionally resampled with
`--transform-spikemask`; the combined native quality masks are not.
See [Outputs and QC](outputs.md) and [Derivative formats](data_reference.md)
for file locations and naming.

## MRSI orientation correction

Post-quantification MRSI maps occasionally come out of the vendor/quantification
pipeline with a wrong sform/qform -- close enough to plausible that spike
filtering, PVC, and even MRSI-to-T1w registration all "succeed", but the whole
recording ends up subtly or badly misaligned. `--correct-mrsi-orientation`
applies an optional correction to the writable derivative copies: before any MRSI preprocessing runs, it
does a quick rigid-only registration of the reference metabolite map (`--ref-met`)
to the T1w anatomical, then applies that same rigid correction to every other
metabolite/CRLB/SNR/FWHM map, in place, at native MRSI resolution (shape and
voxel spacing are unchanged; only position/orientation is corrected).

```bash
mrsiprep-docker /path/to/bids /path/to/derivatives participant \
  --participant-label S001 --session-label V1 \
  --metabolites CrPCr,GluGln,GPCPCh,NAANAAG,Ins \
  --ref-met CrPCr \
  --correct-mrsi-orientation
```

Off by default -- most recordings do not need it, and the real (deformable)
MRSI-to-T1w registration that runs afterward already tolerates ordinary
misalignment. Uses `--registration-backend` (ANTs `Rigid`, or FLIRT `dof=6`
for `fsl`).

See [Command-Line Arguments](cli_reference.md) for the full flag reference,
including `--bids-filter-file` for disambiguating raw T1w acquisitions.
See [Preparing inputs](inputs.md) for geometry requirements.


## Longitudinal recordings

For repeated sessions, [Longitudinal processing](usage_longitudinal.md) builds
a shared subject template with ANTs before mapping each session to MNI.
It requires the ANTs backend and changes the transform chain while keeping
the ordinary per-session derivative layout.
